- **The "Now" feature I'm scoping (name + one-line core description):** One-Click Compliance Checklist Quick Win Largest absolute drop in the funnel (−23 pts, 32% relative) and a 5× time gap (14.6 vs. 3 min). Effort 2 holds only with scope limited to pre-fill from existing data. Parallel track: dashboard reliability Bug fixes for BUG-2044 (8–15 min reassignment delay) and BUG-2072 (20–60 min dashboard lag). Outside feature prioritization, but it uses pilot capacity. Effort TBD, pending a 1-week root-cause spike (assumed E3 for capacity planning).
- **My finalized Must-Haves (after overriding the AI):** M1 – Pre-fill from existing RouteLogic data. Every checklist field that the system already holds (e.g., vehicle, driver, route from the preceding Route Assignment step) is populated automatically. This is the core of the time reduction. M2 – Confirm-all with exception editing. The Coordinator confirms all pre-filled values in one action and edits only the fields that are wrong or empty. Without it, pre-fill still forces field-by-field review. M3 – Empty-field highlighting. Fields with no system data are clearly marked for manual entry, so the Coordinator doesn't have to scan the whole form to find what's missing. M4 – Same compliance record as today. The submission produces the same record, with the same regulatory validity, as the current flow. Without it the Coordinator cannot use the feature at all. M5 – Preserve existing step tracking. The new flow fires the same step-completion and time-on-task events as today. Without them the primary metric and the go/no-go break.
- **What I demoted from Must → Should/Won't, and why:** Nothing, I just splitted Won't 1 in 2 separate items: W1a – AI suggestions for fields with no system data. Won't now. V2 candidate if the pilot shows that manual fields remain the main time cost; the Coordinator still confirms every value. W1b – Auto-submission. Won't, regardless of opt-in, until Compliance/Legal confirms that a record without human confirmation is valid.
- **One thing my PRD makes explicit that a vague brief would have missed:** pre-filled data can be wrong. A brief like "pre-fill the compliance form" would have shown every value as if it were true. My PRD ties that risk to evidence, BUG-2072's 20–60 min dashboard lag, and turns it into a rule: any value updated more than 15 minutes ago is flagged and must be verified on its own before "Confirm all". Without that rule, the feature would save time but repeat the exact trust problem that drives Coordinators to the WhatsApp group (UXR-02).
